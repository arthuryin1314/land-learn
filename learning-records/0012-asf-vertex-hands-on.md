# 动手用 ASF Vertex 查江苏数据；数字与 API 查询一致

用户自己在 Vertex 里框选江苏，用 SLC + IW + 升轨，查到 Path 142/69/171 分别是 1315/1470/1537 景，和 10-16 用 API 查的结果完全一致。还找到了练习用的 2019-01-22 那一景。用户自己得出结论："降轨比升轨少得多，所以论文只能引用别人的研究来说明水平运动可以忽略"。

**纠正**：
1. 查降轨 76 时没有把 Direction 改成 Descending，搜到的是元数据里标成"升轨"的 5 景（1B，2019-02-04，22:05 UTC）。降轨 76 实际有 312 景，确实少，但不是 5 景这个量级。
2. 这 5 景的过境时间是北京时间早上 6 点，帧号也和降轨 76 相同，按"晨昏轨道：降轨在早上"的原理判断，应是元数据标错了。这正好是用原理去检验数据的例子。
3. 结论的方向对，但 P08 不只是引用：它在有升降轨的区域自己算了水平形变（图 S4，不显著），再加上既往研究（P08 p.6）；P06 是引用文献（P06 p.6）。

**Implications**：用户愿意动手查数据，并能从数据里自己推出结论，这种做法要多用。"原理 3：降轨在早上、升轨在傍晚"这次有了一个实际用途（检验元数据），复习时可以拿这个例子来考。
