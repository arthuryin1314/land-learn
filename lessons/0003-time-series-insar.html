时序 InSAR：配对网络、解方程、查错

25 分钟。学完后你能解释"为什么用 SBAS""每期影像配几对"，并能看懂论文方法部分里那一串基线阈值。

开课前：回顾（不看笔记）
  1. 两景影像的相位相减后，噪声能消掉吗？
  2. 江苏只有升轨数据的地方，InSAR 测出来的形变有什么局限？要怎么处理？
核对答案 1. 不能。相减只能消掉"散射常数"（前提是地物没变），噪声每次不一样，消不掉。本课会讲怎么用很多景影像把噪声平均掉。
2. 只能测到视线方向，分不清垂直和水平。要换成垂直沉降，只能假设水平运动可以忽略，再除以 cos θ（P06、P08 都这样做，并给出了依据）。
本课目标

一张干涉图只告诉你两个日期之间变了多少，还混着噪声和解缠错误。你论文第一章要的是每个点在每个日期沉了多少（时间序列）和平均每年沉多少（速率图）。本课讲中间这一步怎么做，也就是"时序 InSAR"。

1. 两种"基线"：挑哪些影像来配对

做干涉之前，要决定哪两景配成一对。论文里总会出现两个阈值，比如 P05 写"时间基线 60 天、垂直基线 200 m"（P05 p.6）：

  • 时间基线：两景相隔多少天。间隔越长，地物变化越大，时间失相干越严重（就是你上次总结的"间隔长，中间就可能发生大变化"）。
  • 垂直基线：两次拍摄时卫星位置相差多远（垂直于视线方向的距离）。相差越远，两次"看"的角度越不同，就会出现几何失相干。
▶ 动画 1：时间基线（同一块地，隔多久再拍）
▶ 动画 2：垂直基线（同一个像素，换个位置再看）
怎么看动画 2：一个像素里有好几个东西在反射（土块、秸秆、屋角……），卫星收到的是它们回波的叠加，就像几个复数相加（灰色小箭头首尾相接，彩色粗箭头是和）。换个位置看，各散射体之间的距离差变了，每个小箭头转的角度不一样，加出来的结果就变了。两次的"和"对不上，相减就没有意义。这跟第 1 课讲的"地物变了，常数消不掉"是同一个道理，只是这次变的不是地物，而是看的角度。
两个动画里的相干性数值、位置差都是示意（比例被放大了），用来看趋势，不是实测值。

对 Sentinel-1 来说，轨道控制得很紧，卫星被维持在一个直径约 100 m（均方根）的"管道"里飞行[1]，垂直基线通常不大。所以真正卡脖子的主要是时间基线。这也是 HyP3 这类服务习惯按"每期和后面几期配对"来安排的原因。

按顺序试三件事：

  1. 拖到 1 对：每期只和下一期配，网络是一条链。看读数：一个三角形都没有。为什么这很要命，第 4 节讲。
  2. 拖到 2、3 对：线变密，三角形出现了，额度也跟着涨。这就是上次方案表里 A（3 对）和 B（2 对）的区别。
  3. 勾上"剔除夏季"，再把配对数拖回 1 或 2：网络会被切成好几段，夏季中间的影像成了"孤岛"。P06 正是这样：剔除夏季干涉图后，"没有连进最终干涉网络的影像也被弃用"（P06 p.5–6）。

3. 从网络解出时间序列：其实是解方程组

每张干涉图给出的是两个日期之间的形变差。设第 0 期是起点（形变记为 0），要求的是第 1、2、3 期各沉了多少（d₁、d₂、d₃）：

干涉对 (0,1)：  d1        = 观测值 a
干涉对 (1,2)：  d2 - d1   = 观测值 b
干涉对 (0,2)：  d2        = 观测值 c
干涉对 (2,3)：  d3 - d2   = 观测值 d
干涉对 (1,3)：  d3 - d1   = 观测值 e

5 个方程，3 个未知数 → 用最小二乘求解

这就是"时序反演"。程序员看来就是解一个线性方程组。有两点要注意：

  • 方程比未知数多（有冗余），噪声会被平均掉。回答了开头的回顾题：单张干涉图消不掉噪声，但很多张干涉图联合求解，噪声就被压下去了。
  • 网络断开就解不了。如果 {0, 1} 和 {2, 3} 之间没有任何干涉对，你只知道两段内部各自怎么变，却不知道两段之间差多少。这就是模拟器里"被切成几段"的后果。

论文里的说法：P05 和 P01 用奇异值分解（SVD）求解（P05 p.6；P01 p.4），SVD 的一个好处就是网络断成几段时也能给出解。

4. 相位闭合：用三角形查出解缠错误

第 1 课说过，形变太快或者失相干时，解缠可能数错圈，错就错整整一圈（视线向约 2.8 cm）。怎么发现？靠三角形：

三期 i、j、k，三张干涉图本来应该满足：
  (i→j) + (j→k) - (i→k) = 0

正常：  1.2 cm + 0.8 cm - 2.0 cm = 0          ✓
(i→k) 解缠时少数了一圈，变成 2.0 - 2.8 = -0.8 cm：
        1.2 cm + 0.8 cm - (-0.8 cm) = 2.8 cm  ✗ 正好差一圈 → 被抓到

这就是相位闭合（phase closure / loop closure）。你的文献里：

  • P04 用闭合差 ∇φij + ∇φjk − ∇φik = 0 来消除解缠错误，原因是华北平原夏季作物生长导致低相干（P04 p.5）；
  • P12 更"狠"：一个像元只要参与的任何一个闭合环超过 |π|，就整个剔除。作者解释说，伊朗的沉降区大多是农田，植被区更容易失相干、更容易解缠出错（P12 p.4）；
  • P08 在 MintPy 里用"桥接"和"相位闭合"两种方法改正解缠错误（P08 p.4）。
所以"每期配几对"不只是钱的问题
  • 1 对：一条链，没有三角形，解缠错了也查不出来，一断就散。不能用。
  • 2 对：有三角形，能做闭合检查，冗余也有了。这是合理的下限。
  • 3 对及以上：更稳，额度也更多。

文献里的做法：P04 每景和后面两景配对（P04 p.5）；P11 用 HyP3 设时间基线 36 天（P11 p.4），在 12 天一期时大约就是往后配 3 期；P08 每景和前后各 5 景配对，每个 frame 超过 900 对（P08 p.3）。江苏又是农田多、易失相干的地方，和 P12 的情况相似，所以方案 B（2 对）是底线，A（3 对）更稳。这一条带去和导师讨论。

5. SBAS 和 PS：两种时序方法

PS（永久散射体）SBAS（小基线集）
用哪些点整个时间段里散射都很稳定的点，多是建筑等人工目标（P11 p.1）"分布式散射体"，靠只用短时空基线的干涉对来保住相干性（P11 p.1；P05 p.6）
优点在这些稳定点上精度和可靠性更高（P11 p.2）在植被区、农村地区能得到多得多的点（P11 p.2；P05 p.6）
缺点农田、自然地表上点很少在 PS 点位置上精度和可靠性通常低一些（P11 p.2）
你的文献P02（湄公河）P04、P05、P08、P11；P03、P07 两种点都用

对江苏来说：第二章要比较"农田和楼房"的沉降，如果只有楼房上有点，第二章就没法做。所以选 SBAS，理由和 P05 一样：要尽量多保住自然地表上的点。你计划用的 MintPy 就是 SBAS 类的工具[2]，P08、P11 都用它（P08 p.4；P11 p.4）。

⚠ AI 可能坑你的地方
  • "配对越多越好"：冗余确实更好，但每多一对都要额度和时间。要算账：AI 很少替你考虑 HyP3 每月 8000 的额度。
  • "只用 PS-InSAR 就行"：AI 可能因为 PS 精度高而推荐它，但你的第二章需要农田上的点。
  • 剔除干涉图不看网络：照搬 P06"剔除夏季干涉图"的做法时，一定要检查网络有没有断开。MintPy 的网络修改步骤会处理这件事，但你要能看懂它的基线图。
  • 把线性速率当成全部：速率图是对时间序列做直线拟合得到的。采矿这类强烈非线性的形变，直线拟合会低估（P06 p.13 的徐州案例）。

参考答案

一张干涉图只给出两个日期之间的形变差，还带着噪声和可能的解缠错误。把很多张干涉图联合起来，相当于解一个方程比未知数多的方程组，冗余能把噪声平均掉；同时三张干涉图组成的三角形可以做相位闭合检查，发现数错圈的解缠错误。只配 1 对时网络是一条链，没有三角形，也没有冗余，所以每期至少配 2 对；但配得越多，HyP3 额度和处理时间越多，所以要在 2 到 3 对之间权衡。选 SBAS 是因为它用短基线干涉对保住了分布式散射体，在农田和农村地区能得到比 PS 多得多的点，而第二章需要比较农田和楼房的沉降。

答疑

答疑 1：SVD 和最小二乘有什么区别？

一个是"目标"，一个是"算法"。最小二乘是目标：找一组每期的形变 d，让"观测值 − 预测值"的平方和最小。SVD（奇异值分解）是实现这个目标的一种算法，可以理解为求矩阵的"伪逆"。

  • 网络连通时：最小二乘只有唯一解，SVD 算出来的就是这个解，两者没有区别。
  • 网络断开时：方程组"秩亏"（rank deficient），段与段之间的偏移可以任意取，满足最小二乘的解有无穷多个。普通公式 inv(AᵀA)·Aᵀ·y 会直接报错，SVD 则从无穷多个解里挑出范数最小的那一个。这个"最小"是算法附加的假设，不是数据测出来的。

MintPy 实际怎么做（依据它的源码和默认配置[M1][M2]）：

  • 求解用 scipy.linalg.lstsq。源码注释写明它底层是 LAPACK 的 gelsd，"computes the minimum-norm solution … using the singular value decomposition"，也就是用 SVD 求最小范数的最小二乘解。所以在 MintPy 里，这两个词说的是同一件事的两个层面。
  • 网络不连通时，它会打印警告："the network is NOT fully connected. Inversion result can be biased! Continue to use SVD to resolve the offset between different subsets." 意思是结果可能有偏差，正是第 3 节说的"能算出数，不等于这个数可信"。
  • 默认用加权最小二乘（weightFunc = var），可靠的干涉图权重大。配置文件注明：原始 SBAS（Berardino et al., 2002）相当于 minNormVelocity = yes 加 weightFunc = no（等权）。
答疑 2：MintPy 的基线图长什么样？

MintPy 用 plot_network.py 画网络，默认输出 4 张图[M3]：pbaseHistory.pdf（每期影像的垂直基线随时间变化）、coherenceHistory.pdf（相干性随时间变化）、coherenceMatrix.pdf（相干性矩阵）、network.pdf（配对网络）。论文附录里的"基线图"一般就是最后这张。下面按它的画法仿了一张，数据是模拟的：

▶ 仿 MintPy network.pdf（模拟数据，鼠标移到线上看详情）

怎么读这张图：

  • 黑点 = 一期影像，横坐标是日期，纵坐标是这期影像相对参考影像的垂直基线。
  • 实线 = 保留下来的干涉对，颜色是这张干涉图的平均空间相干性（仿 MintPy 默认色表：红 = 低，蓝 = 高，显示范围 0.2–1.0）。
  • 虚线 = 被剔除的干涉对（图例里写作 "Ifgram dropped"）。MintPy 的相干性剔除规则：平均相干性低于 0.7、并且不在最小生成树里的才剔掉。最小生成树保证剔完之后网络仍然连通。这个功能默认关闭（mintpy.network.coherenceBased 默认为 no），要自己打开；P08 打开了，阈值 0.7（P08 p.4）。

和动画 3、配对网络模拟器对照着看：同样是"点 + 连线"，MintPy 只是多了"按相干性着色"和"剔除的画成虚线"两层信息。到第 7 课真跑 MintPy 时，你会拿到自己数据的这张图。

  1. P05 为什么选 SBAS 而不是 PS？用了多少景影像、什么阈值、得到多少干涉对？
    P05 第 6 页 "3.1. SBAS-InSAR" 第一段
    核对答案为了减轻复杂山区地形和异质植被造成的严重时间失相干（平均相干性 < 0.8），选 SBAS，因为它利用分布式散射体，能最大化相干像元密度。103 景，时间基线 60 天、垂直基线 200 m，得到 310 个干涉对。
  2. P08 每景和几景配对？每个 frame 有多少干涉图？在 MintPy 里怎么筛选干涉对、怎么处理解缠错误？
    P08 第 3 页（配对）和第 4 页（MintPy 部分）
    核对答案每景和前后各 5 景配对，每个 frame 超过 900 个干涉图。MintPy 中：相干性阈值 0.7；以平均相干性的倒数为权重建立最小生成树（MST）；平均相干性低于阈值且不在 MST 里的干涉图被剔除；用桥接和相位闭合两种方法改正解缠错误。
  3. P04 的相位闭合公式是什么？作者为什么担心华北平原的解缠错误？
    P04 第 5 页 "SBAS-InSAR" 段落
    核对答案∇φij + ∇φjk − ∇φik = 0。因为华北平原夏季作物生长导致低相干，可能引起解缠错误。另外配对方式是"前一景必须和后两景各配一对"，时间基线 80 天、垂直基线 250 m。
  4. P12 怎么处理闭合误差？作者自己承认这种做法"有破坏性"，为什么仍然要这样做？
    P12 第 4 页（方法部分，LiCSBAS 质量检查那一段）
    核对答案只要一个像元参与的任何一个闭合环的闭合差超过 |π|，就把这个像元从时间序列中剔除。原因是伊朗大多数沉降区是农田，植被区更容易失相干，也更容易产生解缠错误。参考点选所有闭合环 RMS 最小的像元。
  5. P06 剔除夏季干涉图之后，还弃用了哪些影像？结合本课的模拟器，说说为什么要弃用。
    P06 第 5–6 页，夏季大气问题那一段的结尾
    核对答案没有连进最终干涉网络的影像也被弃用，所以实际用的影像少于存档。原因（本课内容）：这些影像不出现在任何干涉对里，没有方程把它们和其他日期联系起来，求不出它们的形变。
